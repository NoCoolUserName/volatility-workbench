# Themes and visual references

Workbench themes change the presentation of the application. They do not alter
evidence, plugin availability, analysis settings, saved output or report contents.
Choose a theme from the Theme control in Workbench's header or Settings →
Appearance. Both use the same catalog. The choice is saved in application
preferences and updates other open Workbench tabs. Existing Matrix, Mono and Blue preferences
remain supported as Matrix green, Soft black and white, and Light blue. A browser
without a saved preference starts with the original Matrix green appearance.

The skins use a shared set of application colors, CSS surfaces and locally packaged
decorative art. Forensic tables and controls remain application UI; their content is not
rendered into background artwork. No theme downloads assets or requests an
external page at runtime. The links below document visual references and release
scope; they are not application dependencies.

Theme names appear in the selector. The artwork band has no caption or tagline;
the three plain classic themes omit that band entirely. Fallout 2 replaces the
artwork band with a compact CSS ventilation rail. Selected controls use an even
border without a one-sided inset stripe; Fallout 2 adds a symmetric bevel.

The Fallout 2 skin uses the user's inventory-screen reference as a visual concept.
Its metal frame, rivets, ventilation slots and bevels are CSS gradients, borders
and shadows, so the housing scales with the interface. It does not stretch the
reference screenshot over the application. Subtle edge rust, tarnished slotted
fasteners and small brass vent collars add a restrained post-apocalyptic mechanical
feel. Cases, reports, plugin tables and console output remain selectable text on
opaque dark screen surfaces, with green
labels and phosphor accents. The same treatment covers Settings and adapts to
narrow screens. These overrides apply only to Fallout 2; Matrix and the other
Fallout palettes retain their existing presentation.

## The Punisher reference correction

The requested reference was “Jim Lee War Journal #53 cover.” The issue number
and artist do not match. [Marvel's issue page](https://www.marvel.com/comics/issue/22210/punisher_war_journal_1988_53)
identifies Punisher War Journal (1988) #53 as April 1993 and lists Gary Kwapisz as
penciller. Marvel's cover-credit field is unavailable; the
[Grand Comics Database entry](https://www.comics.org/issue/97128/) separately
credits the signed cover pencils and inks to Gary Kwapisz.

The verified #53 cover shows a red field crossed by black diagonal ink strokes,
navy tactical clothing, a white skull, yellow edge highlights, olive webbing,
pale aqua spent casings and tangled barbed wire. Those cues inform a simplified
skin using diagonal action strokes, midnight armor and a pale skull insignia.
Its decorative artwork is original; it does not embed or reproduce the comic
cover or label it a Jim Lee cover.

## Local artwork provenance

Theme illustrations are original local artwork, rather than downloaded game,
film or comic assets. Theme names identify the requested inspiration and do not
imply affiliation with their rights holders. Geometric decorations use the shared
theme system so the same interface remains maintainable across skins.

`src/volatility_workbench/static/halloween-night.png` is an original raster
background generated with the built-in image generation tool. Its art direction
was:

> Cinematic realistic October night, bare trees, distant gothic house, pale moon,
> mist, two carved pumpkins on right; panoramic 3:1; almost-black left negative
> space; charcoal/slate/amber/bone; no text/logos/gore/people.

The image ships inside the application package and is served locally. It is
decorative and contains no case data.

## Readability and limits

Shared theme tokens keep table surfaces, primary text, secondary text, borders,
controls, warnings and focus indicators consistent. Decorative scenes stay
behind the interface instead of behind dense table text. Statuses retain text
labels as well as color. Keyboard focus remains visible, and the selected-report
highlight retains an even border and stronger text across themes. The header's
Theme button stays highlighted while its picker is open. Theme selection uses a
labelled native control and retains normal keyboard operation.
Artwork is static, without animation. A higher-contrast system preference
strengthens borders and reduces decorative artwork; printed views omit the
theme picker and artwork band.

Artwork and palette changes are cosmetic. A theme does not establish forensic
accuracy or imply that a proposed investigation mode exists. Visual checks use
harmless synthetic case data. They cannot cover every browser, display setting,
user stylesheet or assistive technology; users can retain the simpler legacy
themes when those better fit their viewing needs. Choices persist in application
preferences outside cases and the installed bundle, including when browser storage
is disabled or the desktop's loopback port changes. The browser cache supplies the
initial appearance until an authenticated state response arrives. Failed saves
show an inline message and a **Retry save** button. The current page keeps the
choice; retrying saves that selection without requiring a change to another theme.
